# Public Course Builder post audit

Course Builder posts were reachable by slug or ID without checking publication state or soft deletion. The root post page also rendered a draft banner instead of denying access.

Public readers now require `fields.state = 'published'` and `deletedAt IS NULL` for `type = 'post'`. Missing states fail closed. There is no author or preview bypass. The root page returns Next.js `notFound: true`, which produces a 404, rather than rendering an empty page with a 200.

The root post, course-post, and case-study enumeration queries also require `fields.visibility = 'public'`. Private, unlisted, and missing-visibility rows do not enter the generated sitemap. This discovery restriction does not add a new authentication policy to published direct post URLs.

## Build-time sitemap

`package.json` runs `next-sitemap` in `postbuild`. `next-sitemap.js` configures it to read the Next.js build and prerender manifests. There is no independent Course Builder SQL query in that generator. Its root post URLs come from `src/pages/[post].tsx` → `getAllPostSlugs` in `src/lib/posts/get-post.ts`. Filtering that query removes hidden posts from both the static paths and the generated sitemap XML on the next build. Course and case-study static paths use the corresponding guarded enumeration queries in `src/lib/get-course-builder-metadata.ts`.

The sitemap regression test runs the installed `next-sitemap` URL-set and XML generators against a fixture prerender manifest produced from the real `getStaticPaths` function. Fixtures cover published, draft, archived, soft-deleted, missing-state, private, and unlisted posts. Page data tests exercise the actual `getStaticProps` and `getPost` functions, including `preview: true`, and assert the Next.js 404/200 contracts. These are fixture tests, not live HTTP checks.

A new deployment must regenerate the build-time sitemap and replace the old prerender cache. Existing index documents and externally hosted legacy sitemaps are not mutated by this change.
